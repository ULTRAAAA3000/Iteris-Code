# Стратегия запуска: staging, релизы частями, маркетинг

> **Черновик** (17.11.2026). Идея владельца, записана, чтобы не потерялась. Детали (кто что делает, сроки, настройки) уточняем позже; **внедрение процесса staging/релизов, скорее всего, после старта MVP.** Порядок этапов: [main-plan.md](main-plan.md). Состав MVP: [mvp.md](mvp.md).

## 1. Идея в двух словах

1. Домен куплен (iteris-code.org), маркетолог найден.
2. **Сначала дополняем MVP**, пока трафика нет: пишем все уроки (80–110 на язык), доводим минимальный функционал.
3. Когда MVP готов, **маркетинг начинает приводить первых людей.**
4. Параллельно команда переносит разработку на **закрытый staging** (поддомен, недоступный публично), тестирует там.
5. Проверенное **вливается в основной сайт частями**. Для пользователей продукт постоянно развивается: есть повод вернуться и остаться.

## 2. Почему это работает

- **Глубина курсов — буфер времени.** 80–110 уроков на язык человек не пройдёт за неделю. Пока он учится, мы спокойно достраиваем остальное.
- **XP копится сразу.** Всё, что человек заработал с первого дня, не пропадает, когда позже появятся монеты, магазин и достижения (журнал событий позволяет выдать награды задним числом, см. [mvp.md](mvp.md), п. 5).
- **Релизы частями — это ещё и контент для маркетинга.** Каждый релиз: повод для поста, письма, возвращения. Ощущение «живого» продукта.
- **Безопасность.** Сломанное не попадает к пользователям: сначала staging.

## 3. Этапы (черновик)

| Фаза | Что происходит | Статус |
|---|---|---|
| A. Наполнение MVP | Уроки всех языков по шаблону Go (110 уроков, [go-course-authoring.md](go-course-authoring.md)), доводка функционала из [mvp.md](mvp.md). Трафика нет | 🔄 |
| B. Мягкий старт | Маркетинг приводит первых людей, собираем отзывы. Публично только то, что в MVP | 🔜 |
| C. Staging | Закрытый поддомен, отдельная база, свои ключи входа; тесты там | 🔜 (после старта MVP) |
| D. Релизы частями | Календарь релизов (например, раз в 1–2 недели): магазин, достижения, новые проекты, язык интерфейса и т.д. | 🔜 |

## 4. Что понадобится технически (набросок, не решение)

- **Адрес:** например `staging.iteris-code.org` (по аналогии с `dashboard.` из [SETUP.md](SETUP.md)). Cloudflare Pages: отдельная ветка `staging` даёт свой preview-адрес, поддомен привязывается к ней.
- **Закрыт для всех:** Cloudflare Access (вход только по почтам команды) и/или пароль; `X-Robots-Tag: noindex`, чтобы поисковики не видели.
- **Своя база D1** для staging: тестовые данные не смешиваются с живыми; миграции сначала на staging, потом на основной базе.
- **Свои переменные окружения:** `SITE_URL`, `ROOT_DOMAIN`, `COOKIE_DOMAIN`, ключи Google/GitHub **с отдельными адресами возврата** (callback) для staging.
- **Порядок слияния:** `feature-*` → `staging` → проверка → `main` (основной сайт). «Частями» = в `main` попадают отдельные готовые функции, а не вся ветка сразу; для этого функции делаем независимыми, а незавершённое прячем за флагом (переменная окружения, по образцу `GITHUB_CLIENT_ID`).
- **Календарь и заметки о релизах:** запись в «Историю изменений» [about.md](about.md) уже есть; позже её можно показывать пользователям как «Что нового» (связано с внутренней почтой, этап 6).

## 5. Риски и вопросы

- **Q8 (публичный репозиторий).** Тексты 80–110 уроков на язык лежат в `content/` и читаются всеми на GitHub. Если уроки — главная ценность, лучше решить до маркетинга: приватный репозиторий или хранение уроков вне репозитория. Это самый важный вопрос запуска.
- **Раздвоение стека:** две базы и два набора ключей — больше настроек; нужен чек-лист в SETUP.md.
- **Релизы «для вида» не работают:** каждый релиз должен давать пользователю реальную пользу, иначе эффект «живого продукта» пропадёт.
- **Роли и ответственность:** кто пишет уроки, кто проверяет, кто выкатывает релиз, что делает маркетолог (каналы, бюджет, метрики). Заполнить позже.
- **Метрики для маркетолога:** регистрации, дошедшие до 1-го задания, вернувшиеся на 2-й и 7-й день, средняя глубина прохождения. Сейчас их негде смотреть; нужна хотя бы простая аналитика (этап 6, админка «воронка»).
- **Нагрузка и лимиты:** бесплатные лимиты Cloudflare/D1 и Go Playground (Q6) проверить до первого трафика.
- **Юридическое:** политика конфиденциальности, согласие на cookie, удаление аккаунта и выгрузка данных ([main-plan.md](main-plan.md), п. 5): до маркетинга.
