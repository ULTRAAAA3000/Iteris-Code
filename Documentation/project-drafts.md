# Проекты по ТЗ для Python, Java и Go (черновики)

> Статус: **черновики, не опубликованы** (19.11.2026). Файлы лежат отдельно и не подключены к сайту: их нет в `PROJECTS` (`content/projects/index.ts`), в `/api/project` и в сетке курсов. Публикация после того, как будут дописаны курсы.

## 1. Что сделано

## 2. Как устроена проверка

В отличие от веб-проекта (`js-todo`, где проверки выполняются внутри страницы), здесь программа запускается на сервере через ту же песочницу, что и задания (Go Playground, Wandbox, [task-runtime.md](task-runtime.md)):

1. Берётся код пользователя (функции, типы, классы без `main`).
2. К нему дописывается скрытый **harness**: код, который вызывает функции пользователя с заранее известными данными и печатает для каждого требования `R1 PASS` или `R1 FAIL: причина`.
3. Сервер запускает собранную программу один раз и разбирает вывод: каждое требование получает свой зелёный или красный результат с подсказкой.

Правила сборки по языкам:
- **Python:** harness дописывается в конец `main.py`.
- **Java:** в `Main.java` лежат классы пользователя без `Main`, harness содержит `public class Main`. Заготовка начинается с `import java.util.*;`.
- **Go:** в заготовке уже есть блок `import` со всеми пакетами harness и строки вида `var _ = fmt.Sprint` («не удаляйте»), потому что импорты можно писать только в начале файла. В harness есть таймаут на случай взаимной блокировки горутин.

Harness не читает ввод, файлы и сеть, детерминирован, всегда завершается с кодом 0.

## 3. Как проверено

Тест `tests/projects-draft.test.mjs` по-настоящему запускает все проекты локальными `python3`, `javac`/`java` и `go` (если инструмента нет, язык пропускается):
- эталонное решение проходит все требования, код завершения 0;
- заготовка компилируется, а каждое требование в ней красное;
- в harness нет чтения ввода, файлов и сети.

Дополнительно по каждому проекту вручную проверена одна «неправильная» реализация (ошибка на единицу, не тот порядок и т. п.): хотя бы одно требование краснеет. 30 проверок проходят.

## 4. Что нужно для публикации

1. Дописать курсы (Go до 110 уроков, остальные по шаблону) и уточнить номера уроков в поле `lesson`.
2. Добавить тип проекта с запуском на сервере: `/api/project-run` (или расширить `/api/run`) принимает код, собирает его с harness (harness остаётся на сервере и не уходит в браузер, как и проверки `js-todo`), запускает и возвращает вердикты R1–Rn. Лимиты и учёт XP как у `/api/run` и `/api/progress/complete`.
3. Интерфейс: страница проекта с ТЗ, контрактом, редактором и отчётом по требованиям (существующая страница `js-todo` показывает ту же структуру).
4. Подключить `content/projects-draft/<язык>.ts` в `lib/content.ts` и перенести черновики в рабочую папку.
5. Прочитать ТЗ глазами новичка и при необходимости упростить; проверить фактическую точность формулировок.

## 5. Как добавить или поправить проект

Тип: `content/projects-draft/types.ts`. Проекты: `content/projects-draft/<язык>.ts`, эталоны: `tests/projects-draft/solutions-<язык>.mjs`. После правки запустить `node tests/projects-draft.test.mjs <python|java|go>`.
