| D9 | **Публичный профиль** с готовыми нейтральными аватарами (собственные картинки не загружаются, чтобы не получать нарушения). Владелец предоставит набор аватаров. |
| D10 | Проекты по ТЗ проверяются **автоматически, без ИИ.** Результат пользователь загружает файлом (или пишет в редакторе). |
| D11 | **XP** отражает прогресс и не тратится. **Монеты** тратятся в магазине. За реальные деньги монеты не продаются (до отдельного решения). |
| D12 | **Нормальные индексируемые адреса страниц** (SEO). Сейчас адреса вида `#/lesson/js/3`, их поисковики индексируют плохо. |
| D13 | Практические задания появляются **там, где материал позволяет**, а не «каждые 5–6 уроков» по расписанию. |
| D14 | В подвале сайта: **Powered by VSB** (ссылку даст владелец проекта). |
| D15 | Лендинг: красивые блоки про учебный процесс. Про XP писать можно. Про профили, почту, монеты и магазин не писать. Страниц несколько, не одностраничник. |

## 4. Этапы подробно

### Этап 1. Фундамент: бесплатная платформа и вход 🔜
**Цель:** сайт полностью бесплатный и принимает регистрацию через Google и GitHub.

- [ ] **Удалить Lemon Squeezy:** `lib/billing.ts`, `functions/api/webhooks/payment.ts`, `functions/api/billing/*`, их тесты, переменные `LEMONSQUEEZY_*`, раздел оплаты в `SETUP.md`, кнопки «Перейти на Pro» и «Керування підпискою» в интерфейсе.
- [ ] **Снять пейволл:** все задания бесплатны, поле `premium` и серверная проверка (ответ 402) удаляются.
- [ ] **База данных:** убрать из `schema.sql` поля `portal_url`, `subscription_id`, `billing_updated_at` и таблицу `payment_events`. Поля `is_pro` и `pro_until` оставить как задел под будущие подписки. Если база уже создана с миграцией 0002, подготовить миграцию на удаление (или оставить колонки, они безвредны).
- [ ] **Серия по UTC:** одна функция «какой сейчас день» в одном месте, тесты на границу суток.
- [ ] **Форма входа:** окно или страница «Вход» с кнопками Google и GitHub.
  - Если провайдер не настроен, его кнопка не показывается (вместо сообщения «тимчасово недоступний»).
  - GitHub OAuth: запрос кода, обмен на сервере, чтение профиля и подтверждённой почты.
  - Несколько способов входа: таблица `identities (provider, subject, user_id)`, привязка к одному аккаунту по подтверждённой почте. Текущий `users.id` равен Google ID, нужна миграция.
- [ ] **Задел под перевод:** строки интерфейса выносятся в словарь (английский основной, украинский следом). Контент уроков пока не трогаем.
- [ ] **Мобильная версия** проверяется на каждом изменении (см. раздел 5).

**Готово, когда:** вход через Google и GitHub работает; в коде и интерфейсе нет оплаты; `npm run check` и `npm test` зелёные; страницы помещаются на экране 360–414 px.

### Этап 2. Путь, XP, уровни, серия, календарь 🔜
**Цель:** обучение выглядит как линейка уроков (схема Duolingo, не копия), а кабинет мотивирует возвращаться.

- [ ] **Онбординг при первой регистрации:** язык(и) и уровень (новичок / средний / уверенный). Результат: стартовая глава в пути. Предыдущие главы остаются доступными. (Идея на потом: короткий вступительный тест. Вопрос Q4: дневная цель.)
- [ ] **Путь (линейка):** курс → главы → узлы-уроки (пройден / текущий / доступен). Блокировок нет (D6). Между уроками встают узлы практики (этап 3). Кнопка «Продолжить» ведёт в нужный узел.
- [ ] **XP:** таблица `xp_events (user_id, amount, reason, ref, created_at)` с уникальностью `(user_id, reason, ref)`, чтобы за одно и то же XP не начислялось дважды. Начисление: урок, мини-задание, проект, достижение серии. Формула уровней (порог растёт с уровнем), красивая анимация повышения.
- [ ] **Серия:** анимированный счётчик (огонь), день засчитывается за любое учебное действие (UTC, D5). «Заморозка» серии появится в магазине (этап 5).
- [ ] **Календарь:** сколько уроков и заданий пройдено за день; клик по дню показывает список.
- [ ] **Кабинет:** уровень и полоса XP, серия, календарь, путь.

**Готово, когда:** новичок после регистрации видит свой путь и стартовую точку; XP и уровень растут и не накручиваются повторным прохождением; серия и календарь корректны на границе суток; всё работает на телефоне.

### Этап 2Б. Лендинг, страницы и адреса 🔜
**Цель:** главная страница объясняет учебный процесс и приводит людей из поиска. Делается сразу после этапа 2.

- [ ] **Главная заново:** красивые блоки-визуализации. Процесс: читаешь урок → мини-задание в терминале → проект по ТЗ → проверка. Превью пути, упоминание XP, список языков, FAQ, кнопка «Зарегистрируйся и учись бесплатно». **Не упоминаем** профили, почту, монеты, магазин (D15).
- [ ] **Несколько страниц** с переходами: Главная, Курсы (каталог), Как это работает, О проекте.
- [ ] **Подвал:** Powered by VSB (ссылка позже, D14).
- [ ] **Нормальные адреса (D12):**
  - История браузера (History API) вместо `#/`;
  - адреса вида `/learn/<курс>/<урок>` с английскими `slug` у каждого урока;
  - при сборке создаются готовые страницы уроков (сейчас 162) с `title`, `description`, `canonical`, Open Graph;
  - `sitemap.xml`, `robots.txt`, разметка JSON-LD (учебный материал);
  - старые адреса вида `#/...` продолжают открываться.
- [ ] **Вопрос Q2:** теория уроков открыта без входа (нужно для поисковиков), а прогресс, практика и XP требуют регистрации. Предлагаемое решение, ждёт подтверждения.
- [ ] Цели по Lighthouse: производительность, доступность, SEO не ниже 90 на мобильных.

**Готово, когда:** каждый урок имеет свой индексируемый адрес и красивую карточку при отправке ссылки; главная адекватно выглядит на телефоне.

### Этап 3. Практика и проекты по ТЗ 🔜
**Цель:** главное отличие платформы. После нескольких уроков человек получает ТЗ и делает небольшой продукт.

- [ ] **Типы упражнений:** тест; мини-задание в терминале (уже есть для JS); задание с кодом; **проект по ТЗ**.
- [ ] **Правило D13:** практика добавляется там, где материал уже позволяет, а не по расписанию.
- [ ] **Проект по ТЗ:**
  - страница ТЗ: список требований (R1…Rn), данные и макет;
  - пользователь делает работу и загружает файл или zip (или пишет в редакторе);
  - проверка по требованиям: отчёт «выполнено 6 из 8» с подсказками.
- [ ] **Как проверяем без ИИ (по языкам):**
  - веб (HTML/CSS/JS): страница запускается в изолированном окне (`iframe sandbox`), скрипты проверяют DOM и поведение;
  - JavaScript: Web Worker (уже есть);
  - Python, SQL, TypeScript: WebAssembly в браузере (отдельный этап работ);
  - Go, Java, C++, PHP: в браузере нормально не запускаются; решение откладываем (вопрос Q6).
- [ ] Первые 2–3 проекта: веб и JavaScript (вопрос Q5).
- [ ] Задания для Python, SQL и TypeScript; несколько файлов в одном задании.
- [ ] **Ограничения:** проверка в браузере принципиально обходима (можно подделать запрос). Поэтому награды ограничены лимитами и выдаются один раз.

**Готово, когда:** первый проект по ТЗ можно пройти от начала до зелёного отчёта на телефоне и на компьютере.

### Этап 4. Публичный профиль 🔜
**Цель:** человек делится прогрессом, это бесплатная реклама.

- [ ] **Адрес** `/u/<ник>`; уникальный ник с правилами; настройка «публичный или закрытый» (рекомендация: закрытый по умолчанию, вопрос Q3).
- [ ] **Аватары:** только готовый набор нейтральных человечков (предоставит владелец), выбор из списка. Своих картинок не загружаем.
- [ ] **Био:** короткий текст, только текст, лимит длины, кнопка «пожаловаться».
- [ ] **Содержимое:** календарь активности как на GitHub, изучаемые языки и прогресс по ним, число пройденных заданий и проектов, уровень и серия. Email и персональные данные не показываются.
- [ ] **Шеринг:** кнопка «скопировать ссылку»; красивая карточка при отправке (Open Graph и Twitter Card). Для этого сервер отдаёт мета-теги профиля; картинка-превью делается по шаблону.

**Готово, когда:** ссылку на профиль можно отправить в мессенджер и увидеть красивую карточку; закрытый профиль никому не виден.

### Этап 5. Монеты, магазин, достижения 🔜
**Цель:** задел на будущий заработок и дополнительная мотивация. Всё бесплатно (D1).

- [ ] **Журнал монет** `coin_ledger (user_id, delta, reason, ref, created_at)` с уникальностью `(user_id, reason, ref)`. Баланс считается из журнала.
- [ ] **Выдача** (суммы решим позже): первое выполнение сложных заданий и проектов; серия 7, 14, 30… дней; повышение уровня; заход раз в неделю.
- [ ] **Защита от накрутки:** награда один раз за действие, суточный лимит, идемпотентность.
- [ ] **Магазин:** оформление (темы, рамки профиля), дополнительные задания (2–3 на язык), заморозка серии, дополнительные материалы.
- [ ] **Достижения** (значки) в профиле.
- [ ] Монеты за деньги не продаются, основной учебный материал за монеты не закрывается.

**Готово, когда:** монеты нельзя получить дважды за одно действие, баланс всегда сходится с журналом, покупка и расход отражаются сразу.

### Этап 6. Почта, админка, монетизация 🔜
**Цель:** управление платформой и первый заработок. Тонкостей много, разбираем отдельно.

- [ ] **Внутренняя почта** (референс: Chess.com, уточнить): раздел «Сообщения» в кабинете, новости и изменения, «непрочитано». Рассылка на email позже, с согласием и отпиской.
- [ ] **Админка:** пользователи, воронка (где бросают), рассылки, жалобы на био, выдача монет, роли.
- [ ] **Монетизация** (когда появится аудитория): лёгкая реклама (баннер согласия на cookie) и/или небольшие подписки с плюшками. Платёжка выбирается отдельно (не Lemon Squeezy).

## 5. Правила для каждого этапа

- **Мобильная версия обязательна:** проверка в реальном браузере на 360, 390 и 414 px, без горизонтальной прокрутки, кнопки удобно нажимать, на телефоне простой редактор вместо Monaco.
- **Тесты и типы:** `npm run check`, `npm test` и тест интерфейса зелёные перед каждым пушем.
- **Безопасность:** защита от CSRF, проверка `state` в OAuth, лимиты на запросы, никаких секретов в репозитории.
- **Приватность:** удаление аккаунта и выгрузка данных (нужно добавить не позже этапа 4), согласие на cookie перед рекламой. Платформа учебная, среди пользователей могут быть подростки.
- **Документация:** по окончании этапа обновляем этот файл и [about.md](about.md).
