## 1. Принятые решения

| # | Решение |
|---|---|
| D1 | **Платформа полностью бесплатная на старте.** Lemon Squeezy удаляется. Платёжная система появится позже и будет другой (пока не выбрана). |
| D2 | Цель: **научить языку так, чтобы можно было работать.** Без ИИ-проверок. |
| D3 | Заработок позже: лёгкая реклама и/или небольшие подписки с «приятными плюшками». Это не «платформа на миллион», а комфортная бесплатная платформа, которую легко рекламировать: «полностью бесплатно выучи язык». |
| D4 | Базовый язык платформы **английский**. Украинский и русский появятся позже как переводы. **Сейчас не переводим**, но интерфейс строим так, чтобы перевод был возможен (см. вопрос Q1). |
| D5 | Серия и «день» считаются по **UTC** (международное время, не меняется летом и зимой). |
| D6 | **Свободная навигация:** любой урок доступен в любой момент, блокировок нет. Есть рекомендованный путь. |
| D7 | При первой регистрации пользователь **выбирает уровень** (новичок / средний / уверенный) и язык. Платформа ставит его в нужное место пути (как в Duolingo). |
| D8 | **Вход через форму:** Google и GitHub. Ключи Google владелец проекта настраивает сам через переменные окружения. |
| D9 | **Публичный профиль** с готовыми нейтральными аватарами (собственные картинки не загружаются, чтобы не получать нарушения). Владелец предоставит набор аватаров. |
| D10 | Проекты по ТЗ проверяются **автоматически, без ИИ.** Результат пользователь загружает файлом (или пишет в редакторе). |
| D11 | **XP** отражает прогресс и не тратится. **Монеты** тратятся в магазине. За реальные деньги монеты не продаются (до отдельного решения). |
| D12 | **Нормальные индексируемые адреса страниц** (SEO). Сейчас адреса вида `#/ref/js`, их поисковики индексируют плохо. После D17 индексируется справочник, а не уроки. |
| D13 | Практические задания появляются **там, где материал позволяет**, а не «каждые 5–6 уроков» по расписанию. |
| D14 | В подвале сайта: **Powered by WYSB**, ссылка на https://wysb.eu (название и ссылка уточнены владельцем). |
| D17 | **Уроки и практика только в аккаунте.** Публично (без входа) виден лишь справочник по языкам, разбитый по направлениям и языкам (`#/ref/<язык>`). Тексты уроков и задания не входят в сборку для браузера: лежат в `content/` и отдаются сервером после входа (`/api/courses`, `/api/lesson`). `/api/run` тоже требует входа. Отменяет прежнюю идею открытой теории (Q2). |
| D16 | **Единый метод запуска практики:** JS выполняется в браузере, все остальные языки на сервере через «песочницу» языка (`POST /api/run`), результат проверяет сервер по списку `checks` и подписывает (`proof`). Для нового языка нужен только адаптер и задания, интерфейс общий. Подробности: [task-runtime.md](task-runtime.md). |
| D15 | Лендинг: красивые блоки про учебный процесс. Про XP писать можно. Про профили, почту, монеты и магазин не писать. Страниц несколько, не одностраничник. |
| D19 | **Герои платформы (айдолы).** 11 персонажей с именами (Мо, Тео, Міка, Нокс, Лулу, Ендрю, Рекс, Зак, Піко, Лімо, Ноа). Они служат готовыми аватарками профиля (замена «нейтральных человечков» из D9) и позже становятся ключевыми фигурами платформы: ведут интерактивное вступление, живут на лендинге, в магазине и так далее. Кто за что отвечает, описано в [idols.md](idols.md) (роли пока черновые, согласуем вместе). |
| D20 | **Запуск (черновик):** сначала дополняем MVP (все уроки, 80–110 на язык, по шаблону Go), затем маркетинг приводит первых людей; разработка уходит на закрытый staging и вливается в основной сайт частями. Подробнее: [launch-strategy.md](launch-strategy.md). Внедрение процесса, скорее всего, после старта MVP. |
| D21 | **MVP (черновик):** без монет и магазина; они идут первым релизом частями после старта, награды выдаются задним числом. Состав и критерии: [mvp.md](mvp.md). |
| D22 | **Напарник** (герой растёт с уровнем и реагирует на события), сценки с эмоциями и ритмы бесед; «Студия Iteris» одобрена как концепция. Будущее, не MVP (подтверждено в D29: герои после запуска). Черновик: [companion.md](companion.md). |
| D23 | **Staging** (закрытый поддомен, своя база и ключи, релизы через PR `staging` → `main`, частями): план внедрения в [staging.md](staging.md), делаем после старта MVP. |
| D24 | **Юридические документы:** оператор данных — AKERR-SHY s.r.o. (Чехия, GDPR); политика и условия на каждом языке сайта, возраст 15+ (спрашиваем при регистрации, не храним; до 18 с согласия родителей). Страницы, удаление и выгрузка данных сделаны. Тексты — черновик до проверки юристом: [legal.md](legal.md). |
| D25 | **Английский — основной язык сайта и главный текст юридических документов** (подтверждение D4): сайт по умолчанию на английском, сверху переключатель на украинский. Входит в MVP, делается после написания всех уроков ([mvp.md](mvp.md)). |
| D26 | **Защита (17.11.2026):** версия сессий (смена пароля и «выйти всюду» отзывают cookie), заголовки безопасности, лимиты и обрезка отправок, жалобы на профили с автозакрытием после 3, CI и Dependabot. Что включить вручную в Cloudflare и GitHub и план на случай инцидентов: [security.md](security.md). |
| D27 | **Взаимодействие между аккаунтами** (черновик идей, не MVP): сначала подписки, лента, реакции, затем друзья-серия и челленджи; свободных чатов нет. [social.md](social.md). |
| D28 | **Дневная цель (Q4):** число «шагов» в день: 1, 2, 3 или 5 (по умолчанию 1). Шаг это урок, пройденный сегодня, или задание, впервые решённое сегодня (повторное решение не считается). Выбирается в онбординге и меняется в кабинете. День считается по UTC, как и серия. Подсказка «серия сегодня под угрозой» показывается вверху кабинета, пока серия есть, а шагов сегодня ещё нет, и называет время (по часам пользователя), до которого нужно успеть. Таблица `user_goals`, `GET/POST /api/goal`. |

| D18 | **Шлях и кабинет только для зарегистрированных.** Пункт «Шлях» в шапке скрыт для гостей (`data-auth`), а адреса `#/path`, `#/path/<курс>` и `#/start` показывают гостю то же приглашение войти, что и уроки (D17), а не сам шлях. |

## 4. Этапы подробно

### Этап 1. Фундамент: бесплатная платформа и вход 🔜
**Цель:** сайт полностью бесплатный и принимает регистрацию через Google и GitHub.

- [ ] **Удалить Lemon Squeezy:** `lib/billing.ts`, `functions/api/webhooks/payment.ts`, `functions/api/billing/*`, их тесты, переменные `LEMONSQUEEZY_*`, раздел оплаты в `SETUP.md`, кнопки «Перейти на Pro» и «Керування підпискою» в интерфейсе.
- [ ] **Снять пейволл:** все задания бесплатны, поле `premium` и серверная проверка (ответ 402) удаляются.
- [ ] **База данных:** убрать из `schema.sql` поля `portal_url`, `subscription_id`, `billing_updated_at` и таблицу `payment_events`. Поля `is_pro` и `pro_until` оставить как задел под будущие подписки. Если база уже создана с миграцией 0002, подготовить миграцию на удаление (или оставить колонки, они безвредны).
- [ ] **Серия по UTC:** одна функция «какой сейчас день» в одном месте, тесты на границу суток.
- [ ] **Форма входа:** окно или страница «Вход» с кнопками Google и GitHub.
- [x] **Вход по почте и паролю** (ветка `feature-email-password-auth`): регистрация, подтверждение почты, «забыли пароль», PBKDF2-хеш, Turnstile на всех формах, лимиты попыток. Настройка: `SETUP.md`, раздел 5.
  - Если провайдер не настроен, его кнопка не показывается (вместо сообщения «тимчасово недоступний»).
  - GitHub OAuth: запрос кода, обмен на сервере, чтение профиля и подтверждённой почты.
  - Несколько способов входа: таблица `identities (provider, subject, user_id)`, привязка к одному аккаунту по подтверждённой почте. Текущий `users.id` равен Google ID, нужна миграция.
- [ ] **Задел под перевод:** строки интерфейса выносятся в словарь (английский основной, украинский следом). Контент уроков пока не трогаем.
- [ ] **Мобильная версия** проверяется на каждом изменении (см. раздел 5).

**Готово, когда:** вход через Google и GitHub работает; в коде и интерфейсе нет оплаты; `npm run check` и `npm test` зелёные; страницы помещаются на экране 360–414 px.

### Этап 2. Путь, XP, уровни, серия, календарь ✅
**Цель:** обучение выглядит как линейка уроков (схема Duolingo, не копия), а кабинет мотивирует возвращаться.
Ветка `stage-2-path-xp`. Сделано параллельно с этапом 1 (см. «Где этап 2 трогает общие файлы» ниже).

- [x] **Онбординг при первой регистрации:** курсы (до 5) и уровень (новичок / средний / уверенный). Результат: стартовая глава в пути, предыдущие главы остаются доступными. Таблица `user_onboarding`, `GET/POST /api/onboarding`, страница `#/start` для смены выбора. (Идея на потом: вступительный тест. Вопрос Q4: дневная цель.)
- [x] **Путь (линейка):** страница `#/path/<курс>`: курс → главы → узлы-уроки (пройден / текущий / доступен / до старта). Блокировок нет (D6). Кнопка «Продолжить» ведёт в нужный узел. Узлы практики показываются там, где уже есть задание (JS); новые добавит этап 3.
- [x] **XP:** таблица `xp_events` с уникальностью `(user_id, reason, ref)`, начисление идемпотентно (`POST /api/xp/sync` и при открытии кабинета). Источники: урок +10, задание (его `xp`), бонус за серию 3/7/14/30/60/100 дней. Уровень растёт по формуле `порог(n) = 40 + 20n`. Всплывающее «+XP» и окно повышения уровня с конфетти. XP за проект и достижение добавят этапы 3 и 5.
- [x] **Серия:** анимированный счётчик с огнём (горит, если сегодня была активность), полоса последних 7 дней, подсказка до ближайшего бонуса. Серию по-прежнему считает `lib/session.ts`; **единая функция «какой сейчас день (UTC)» остаётся за этапом 1** (D5).
- [x] **Календарь:** по клику на день список пройденных уроков и заданий, подсчёт за день, доступно с клавиатуры.
- [x] **Кабинет:** уровень и полоса XP, серия, календарь, карточка «Ваш шлях».
- [ ] «Заморозка» серии: в магазине, этап 5.

**Готово, когда:** новичок после регистрации видит свой путь и стартовую точку; XP и уровень растут и не накручиваются повторным прохождением; серия и календарь корректны на границе суток; всё работает на телефоне. Проверено на 360 и 390 px.
Миграция для готовой базы: `migrations/0010_stage2_xp_onboarding.sql` (для новой достаточно `schema.sql`). С PR #6 таблицы этапа 2 также создаются автоматически (`lib/schema.ts`).

## 5. Правила для каждого этапа

- **Мобильная версия обязательна:** проверка в реальном браузере на 360, 390 и 414 px, без горизонтальной прокрутки, кнопки удобно нажимать, на телефоне простой редактор вместо Monaco.
- **Тесты и типы:** `npm run check`, `npm test` и тест интерфейса зелёные перед каждым пушем.
- **Безопасность:** защита от CSRF, проверка `state` в OAuth, лимиты на запросы, никаких секретов в репозитории.
- **Приватность:** удаление аккаунта и выгрузка данных (нужно добавить не позже этапа 4), согласие на cookie перед рекламой. Платформа учебная, среди пользователей могут быть подростки.
- **Документация:** по окончании этапа обновляем этот файл и [about.md](about.md).
