Усе з [bash-course-authoring.md](bash-course-authoring.md) діє й тут (тег `sh`, маркери блоків, норми, залежності); нижче лише відмінності Git.

## 2. Як запускаються завдання (рішення для курсу)

Завдання Git — це **скрипти Bash** (`lang: "bash"`, файл `main.sh`, спільний запуск із курсом Bash): скрипт створює репозиторій у `mktemp -d`, виконує команди й друкує результат, який перевіряють `checks`. Це варіант (1) із course-template.md.

**Відкрите питання до підключення курсу до сайту:** чи є `git` у пісочниці Wandbox, яку використовує `lib/runners.ts`. Локальний тест гоняє справжній git (зараз 2.43), а Wandbox із цієї сесії недоступний. Якщо git там немає, лишаються два шляхи: власний сервер запуску або заміна завдань на розбір виводу без запуску. Уроки від цього рішення не залежать.

## 3. Детермінований вивід

- **Не друкуйте хеші, дати й шляхи.** Для перевірки використовуйте: `git log --format=%s` (теми), `git rev-list --count HEAD` (кількість), `git status --short` або `--porcelain` (статус), `git cat-file -t`, `git branch --list`, `git diff --stat` не використовуйте (залежить від локалі й терміналу).
- Автор задається **локально** в кожному скрипті (`git config user.name …`, `user.email …`), глобальних налаштувань у пісочниці немає. Для змін історії, де потрібні фіксовані дати, задавайте `GIT_AUTHOR_DATE` і `GIT_COMMITTER_DATE`.
- Гілку створюйте явно: `git init -q -b main` (Git 2.28+). Перемикання через `git switch` (2.23+); згадуйте `git checkout` лише як старий спосіб.
- Тексти повідомлень Git залежать від мови системи, тому в прикладах з порівнянням виводу беріть `--porcelain`, `--short`, `--format`. Повідомлення типу `On branch main` показуйте лише в блоках `# фрагмент:`.
- Інтерактивні команди (`rebase -i`, `add -p`, `commit` без `-m`) у скрипті без клавіатури не працюють: показуйте їх блоками `# фрагмент:`, а виконуваний варіант будуйте через змінні `GIT_SEQUENCE_EDITOR`, `GIT_EDITOR` або пряму підстановку, пояснюючи, що в терміналі це робить редактор.
- Мережі немає: «віддалений» репозиторій створюйте локально (`git init --bare`, шлях `file://` або просто шлях до папки).
- Показаний збій: код 128 (`fatal:`) для більшості помилок Git, код 1 для відмов `commit`/`merge` з конфліктом. Маркер `# аварія:` ставте лише там, де код стабільно ненульовий; для надійності вимикайте вгадування автора (`git config user.useConfigOnly true`).

## 4. Версія

Git 2.28 і новіші (`init -b`, `switch` 2.23, `restore` 2.23, `--force-with-lease` давно). Можливості, новіші за 2.30, позначайте версією в тексті.
