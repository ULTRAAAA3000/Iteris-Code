# Розширення курсів HTML, CSS і SQL: план, норми, тести

> Статус: **план затверджено, уроки пишуться по главах** (23.11.2026). **SQL: усі 10 глав (35 уроків, 35 завдань) написані 24.11.2026**, `SQL_STRICT=1 node tests/sql-course.test.mjs` проходить на справжньому sqlite3; курс чекає перечитування й підключення. Нові уроки лежать окремо в `content/html`, `content/css`, `content/sql` і **не підключені до сайту** (так само, як Go до підключення). Підключення після того, як курс дописано й перечитано.
> Цей документ **замінює** для HTML, CSS і SQL цифри «110 уроків, 12 глав» з [course-template.md](course-template.md): ці три мови не мають матеріалу на 110 уроків без води (розділ 1.6 шаблону: глибина важливіша за число). Решта шаблону (норми уроку, процес, перевірка справжніми інструментами) діє без змін.

## 1. Скільки уроків і чому

| Курс | Було | Стане | Глав | з них `adv` | Старих завдань переїжджає (`keep`) |

| HTML | 12 | **30** | 8 | 7 | 11 з 11 |

- **HTML ≈ 30.** Мова невелика: за 30 уроків можна пройти документ, текст, посилання, медіа, таблиці, форми, семантику, доступність і SEO. Більше було б повторенням.
- **CSS ≈ 40.** Найбільший з трьох: окремі уроки потрібні селекторам, каскаду, одиницям, блочній моделі, потоку, Flexbox, Grid, адаптивності, змінним і анімаціям. У старому курсі в один урок вміщалося по 3–4 теми.
- **SQL ≈ 35.** Основи вибірки, фільтрації й агрегації; схема й зміна даних; JOIN у кількох уроках; підзапити, CTE й VIEW; віконні функції; проєктування, індекси, транзакції. Те, що SQLite не вміє (процедури, рівні ізоляції), подається текстом із позначкою «в PostgreSQL/MySQL».

**Джерело істини** для планів: `content/html/chapters.js`, `content/css/chapters.js`, `content/sql/chapters.js` (формат як у `content/go/chapters.js`: глави, уроки, `adv`, `keep`). Тест звіряє тексти з планом.

## 3. Норми

Поля уроку, норми обсягу (6–7 абзаців теорії, 3–5 прикладів, 450–950 слів, два запитання для самоперевірки) і «шість кроків навчання» беремо з [course-template.md](course-template.md), розділ 1.2, і [go-course-authoring.md](go-course-authoring.md). Додатково для цих трьох мов:

- **Один урок, одне нове поняття, одне практичне завдання.** `lesson` завдання = `<мова>/N` нової нумерації.
- **Маркер навмисної помилки** першим рядком блока коду: HTML `<!-- не валідний: … -->`, CSS `/* не працює: … */`, SQL `-- помилка: …`. Блок без маркера має бути правильним. Фрагмент (неповна сторінка), який не слід перевіряти як документ, позначається так само: HTML `<!-- фрагмент: … -->`, CSS `/* фрагмент: … */`, SQL `-- фрагмент: …`. Тест HTML перевіряє баланс тегів у всіх прикладах, крім позначених «не валідний».
- **HTML і CSS (`runtime: "page"`).** Перевірка в jsdom, **верстки немає**: розміри й позиції перевірити не можна. Кольори пишемо в hex, довжини в px, тільки повні властивості (`padding-top`, не `padding`). Усе, що залежить від ширини екрана, теми, `:hover` і псевдоелементів, перевіряємо за кодом (`source`). Скрипти в передперегляді не виконуються, зовнішніх ресурсів немає (картинки тільки `data:`).
- **SQL.** Запуск через `sqlite3`; перевірки виводу через `has`; завжди `ORDER BY`, якщо порядок потрапляє в перевірку; `UPPER/LOWER` на кирилиці SQLite не працюють. Свої особливості SQLite (типізація за спорідненістю, `ALTER` без `ALTER COLUMN`) позначаємо прямо в уроці.
- **Версії.** HTML і CSS: сучасні браузери; усе, що підтримується не скрізь (`:has`, `@layer`, контейнерні запити), живе в `adv` з позначкою про підтримку. SQLite: віконні функції з 3.25, `RETURNING` і `UPSERT` з 3.35 / 3.24; версію називаємо в уроці.
- **Залежності.** Базовий урок спирається лише на раніші базові (див. розділ 1.5 шаблону).

| SQL | 1→1, 2→2, 3→4, 4→6, 5→9, 6→13, 7→15, 8→17, 9→20, 10→21, 11→26, 12→29, 13→32, 14→34, 15→35 |
