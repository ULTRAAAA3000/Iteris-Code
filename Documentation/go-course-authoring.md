# Курс Go: як писати уроки й завдання

> Інструкція для тих, хто додає або переписує уроки курсу Go (і шаблон для інших мов). Метод запуску завдань: [task-runtime.md](task-runtime.md). Порядок етапів: [main-plan.md](main-plan.md).
> Остання редакція: 16.11.2026.

## 1. Структура курсу

Курс Go складається з **110 уроків у 12 главах** (на сайті поки 99: глави 1–10, глави 11–12 дописуються; до завершення тест курсу запускають із `GO_PARTIAL=1`). Усі вони лежать в одному списку, нумерація наскрізна (`go/1` … `go/110`), прогрес зберігається за цим номером.

- **Базовий рівень: 80 уроків.** Усе, що потрібно, щоб почати працювати на Go.
- **Просунутий рівень: 110 уроків.** Базові уроки плюс 30 уроків із прапорцем `adv: true`.
- Користувач перемикає рівень у будь-який момент (сторінка курсу або «Мій шлях»). Прогрес не губиться: пройдені базові уроки лишаються пройденими в обох рівнях.

**План (джерело істини): `content/go/chapters.js`.** Там назви уроків, межі глав, прапорці `adv` і список id завдань зі старої версії курсу (`keep`). Тест звіряє тексти з планом.

**Головне правило залежностей.** Базовий урок спирається лише на раніші **базові** уроки. Просунутий урок може спиратися на базові й на раніші просунуті. Інакше користувач базового рівня зустріне незнайоме поняття. Якщо базовому уроку потрібна річ із просунутого (наприклад, `slices.Sort`), він вводить її сам, коротко.

Урок може використовувати лише те, що вже пояснено в попередніх уроках (дивіться порядок у `chapters.js`). Про майбутні теми можна згадати одним реченням («про це в главі про помилки»), але не будувати на них приклад.

## 2. Де що лежить

| Файл | Зміст |

| `content/tasks/go/chNN.ts` | Завдання глави: `export const TASKS_NN` |

## 3. Урок

```js
const BT = "`";   // зворотний апостроф: у String.raw його вставляють як ${BT}

export const LESSONS_05 = [
  {
    t: "Інтерфейси",              // точно як у chapters.js
    ch: "Інтерфейси та generics",  // назва глави
    adv: true,                     // лише для просунутих уроків, в базових поля немає
    easy: "…",                     // «Простими словами»: 1–2 речення, життєва аналогія
    p: ["…", "…"],                 // теорія: 5–8 абзаців (мінімум 5 і 1800 символів разом)
    code: [String.raw`package main …`, String.raw`…`],   // 2–4 приклади, від простого до реалістичного
    note: "…",                     // «Запам'ятайте»: головне правило або пастка
    work: "…",                     // «Як це в роботі»: де це зустрічається в реальних проєктах
    tasks: ["…", "…"],             // рівно 2 запитання для самоперевірки (не те саме, що завдання в редакторі)
  },
];
```

**Тексти українською**, ідентифікатори Go англійською. У `p`, `easy`, `note`, `work` дозволені лише теги `<code>`, `<b>`, `<i>`; символи `<`, `>`, `&` пишемо як `&lt;`, `&gt;`, `&amp;`. У `code` текст без розмітки.

### Як навчати, а не переказувати

Урок має вчити так, щоб людина потім могла написати це сама:

1. **Навіщо.** Яку проблему розв'язує тема, і що було б без неї.
2. **Модель у голові.** Як це влаштовано всередині (наприклад, слайс = вказівник + довжина + ємність). Малюнок словами, а не лише синтаксис.
3. **Приклади по сходинках.** Мінімальний приклад, потім із варіаціями, потім реалістичний. Кожен приклад запускається й має передбачуваний вивід.
4. **Пастки.** Типові помилки новачків і що друкує компілятор у такому разі. Покажіть їх (див. маркери нижче).
5. **Ідіоми.** Як це пишуть у реальному коді й чому саме так.
6. **Зв'язок.** Одне речення про те, що буде далі.

Пояснення має бути точним для **Go 1.24**: змінна циклу своя на кожній ітерації (з 1.22), `for i := range 10` (1.22), вбудовані `min`, `max`, `clear` (1.21), пакети `slices` і `maps` (1.21), `log/slog` (1.21), шаблони в `http.ServeMux` (1.22), generics (1.18). Якщо щось залежить від версії, скажіть це.

### Приклади коду й маркери

Кожен блок у `code`, що починається з `package main`, **компілюється і запускається тестом**. За замовчуванням він має завершитися успішно. Для навмисних помилок додайте на початку коментар-маркер (він видимий учню й слугує підписом):

- `// не компілюється: …` блок має дати помилку компіляції (наприклад, невикористана змінна).
- `// аварія: …` блок має впасти під час роботи (panic, deadlock).
- `// лише компіляція: …` блок лише збирається, але не запускається (наприклад, справжній сервер, що слухає порт).

Блоки без `package main` (команди термінала, фрагменти) не запускаються.

### Обмеження Go Playground

Код запускається на сервері через Go Playground (див. task-runtime.md, розділ 5), тому в прикладах і завданнях:

- **немає мережі й stdin.** Сервер HTTP не слухає порт: обробники перевіряємо через `net/http/httptest`; ввід імітуємо через `strings.NewReader`.
- **один файл** `package main`. Пакети, `_test.go` і другий файл неможливі: табличний тест пишемо «вручну» циклом і виводимо `ok`/`FAIL`; «пакети» пояснюємо текстом і прикладами в кількох блоках.
- **детермінований вивід.** Без `time.Now()`, без випадкових чисел (лише `rand.New(rand.NewSource(1))`), без порядку обходу мапи, без залежності від планувальника горутин (синхронізуйте результат каналами, `WaitGroup`, сортуванням).
- **швидкість.** Приклад і еталон мають виконуватися за частки секунди.

## 4. Завдання

Формат і метод описані в [task-runtime.md](task-runtime.md), розділи 3–4. Коротко:

```ts
import type { RemoteTask } from "../../../src/tasks/types.ts";
import { base } from "./base.ts";

const raw = String.raw;
const BT = "`";

export const TASKS_05: readonly RemoteTask[] = [
  {
    ...base, id: "go-shapes-area", lesson: "go/40", xp: 25,
    title: "…", context: "…", brief: ["…", "…"],
    starter: raw`package main …`,
    checks: [ { on: "stdout", name: "…", has: "…" }, … ],
  },
];
```

- **Одне завдання на кожен урок** (110 разом). `lesson` дорівнює `go/N`, де N із `chapters.js`. Порядок у файлі збігається з порядком уроків.
- Якщо в плані є `keep`, використайте саме цей `id` (старе завдання переїхало до цього уроку; його можна й потрібно переписати під новий текст уроку, id лишається).
- Завдання **перевіряє саме тему уроку**, а не «щось виведіть». Додавайте `source`-перевірки, коли треба змусити використати конструкцію (`range`, `defer`, метод із вказівником, `go func`).
- Не менше трьох перевірок: кілька частих (`has`) і одна загальна (`equals`) за потреби `source`. Підказки (`hint`) пишіть так, щоб вони наводили, а не видавали рішення.
- **Заготовка запускається**, `main` закритий (його пише автор), користувач дописує функцію, тип чи метод. Заготовка **не** проходить усі перевірки (тест це перевіряє).
- XP за складністю: 15–20 просте, 25–35 середнє, 40–60 складне (проєкти).
- `title`, `context`, `brief` українською; `context` відповідає на «навіщо це в роботі».

### Еталон

У `tests/solutions/go-chNN.mjs`: `id` → повний код, що проходить усі перевірки. Код пишемо в `String.raw` (як заготовки), тоді `\n` у рядках Go лишається як є; зворотний апостроф вставляємо як `${BT}`. Ключі файлу збігаються з `id` завдань глави (тест звіряє).
